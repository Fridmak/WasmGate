# 07. Глоссарий

> Короткие определения терминов, которые встречаются в коде и документах.
> Нужен, чтобы через месяц не вспоминать, «а что такое RCU».

---

## Сеть и прокси

**L4 (уровень 4).** Транспортный уровень модели OSI: TCP/UDP. Прокси на L4
оперирует **соединениями и байтами**, не разбирая протокол приложения (HTTP и
т.п.). Наш MVP — именно L4.

**L7 (уровень 7).** Уровень приложения: HTTP, JSON, заголовки. Требуется для DPI
(фича F3).

**Reverse proxy (обратный прокси).** Стоит между клиентами и серверами, клиенты
подключаются к прокси, а прокси — к бэкенду. В отличие от forward proxy
(клиент → прокси → интернет).

**Upstream / backend.** Сервер за прокси, куда переправляется трафик.

**Listener.** «Фронтальный» адрес (`host:port`), который прокси слушает.

**Pool.** Группа upstream-серверов, объединённых одной стратегией балансировки.

**Balancer / балансировка.** Алгоритм выбора upstream под новое соединение:
`round_robin` (по кругу) или `least_conn` (где меньше активных).

**Drain (graceful drain).** При остановке перестаём принимать новые соединения,
но даём уже открытым доработать до конца. Ждём не дольше `-shutdown-grace`; после
истечения срока оставшиеся соединения закрываются принудительно (и `Shutdown`
сообщает об этом ошибкой).

**Half-close.** Закрытие только одной половины TCP-соединения (`CloseWrite`),
чтобы сообщить «я закончил писать», но продолжать читать. Важно для протоколов,
где EOF — это сигнал.

**Half-open (полуоткрытое соединение).** Соединение, где одна сторона закрылась
или замолчала, а вторая продолжает ждать. Без idle-таймаута такое соединение может
«висеть» неограниченно долго (утечка горутин и файловых дескрипторов).

**Idle timeout.** Таймаут простоя соединения: если за интервал не передано ни
одного байта **в обоих направлениях**, соединение сбрасывается. Дедлайн
обновляется при активности **любого** направления, поэтому односторонняя передача
(медленное скачивание, SSE) не рвётся. Включается `idle_timeout > 0`; реализован
через read-deadline, поэтому **отключает zero-copy `splice`** для всего соединения;
`idle_timeout: 0` (по умолчанию) сохраняет `splice`.

**SNI.** Server Name Indication — имя хоста в TLS-рукопожатии. Позволяет
маршрутизировать TLS-трафик, **не расшифровывая** его (passthrough).

## Производительность (Go)

**Fast path («горячий путь»).** Код, исполняемый на каждое соединение/запрос.
Цель — **ноль аллокаций** в steady state; блокировок на пути данных нет (в
hot path только атомики, мьютекс есть лишь у лог-лимитера на путях ошибок и
он же — единственное место, где общая кэш-линия может стать узким местом).

**Allocs (`allocs/op`).** Число аллокаций на операцию в бенчмарке. Цель fast
path — `0`. То же и **на соединение**: буферы копирования берутся из пула
(`bufferPool`), а на Linux plain-путь не буферизует вообще — копирует ядро.

**`splice(2)`.** Системный вызов Linux: ядро перекладывает байты между двумя
сокетами **без копии в user space**. `io.Copy` использует его автоматически,
когда сток — `*net.TCPConn`; на других платформах этот вызов недоступен
(цена — в benchmarks/README.md, §«Платформа»).

**Zero-copy.** Передача данных без лишних копирований (у нас — через `splice`).

**Backpressure.** Естественное «торможение» быстрого отправителя медленным
получателем. При горутине-на-соединение работает бесплатно: `io.Copy` просто
блокируется.

**False sharing.** Замедление, когда две горутины пишут в переменные на **одной
кеш-линии** разных ядер. Лечится паддингом; у нас **отложено** до профиля.

**CGO.** Вызов C-кода из Go. Мы **не используем**: проще кросс-сборка, статичный
бинарь. Побочный эффект: `-race` на Windows требует C-компилятора.

**`GOMAXPROCS`.** Число ядер, используемых рантаймом Go.

**pprof.** Встроенный профайлер Go (CPU/heap). Доступен на admin-листенере (`admin_addr`, `/debug/pprof/`).

## Синхронизация и hot reload

**Snapshot.** **Неизменяемая** (immutable) копия конфигурации + скомпилированных
объектов. Читается на каждом соединении. В snapshot **не** попадает состояние,
зависящее от истории (счётчики) — оно живёт в registry.

**Registry (`internal/proxy/state.go`).** Долгоживущее состояние, переживающее
reload: счётчики активных соединений листенеров (`max_conns`), скользящие окна
`rate_limit` и счётчики `active` у бэкендов. Нужен, чтобы reload не сбрасывал
лимиты и не ломал `least_conn`.

**RCU (Read-Copy-Update).** Паттерн: читатели берут указатель на текущую версию
без блокировок; обновление создаёт **новую** версию и атомарно публикует её.
Старые читатели спокойно дорабатывают на прежней версии.

**`atomic.Pointer[T]`.** Типизированный атомарный указатель из stdlib.
`.Load()` — чтение без блокировок; `.Store()` — атомарная публикация.

**Типизированные атомики.** `atomic.Int64`/`atomic.Uint64` вместо
`atomic.AddInt64(&x, 1)`. Дают гарантию выравнивания → безопасно на 32-битных
платформах.

**Zero-Downtime Hot Reload.** Смена конфига/логики **без разрыва** соединений и
без простоя. Реализуется через snapshot + RCU.

**Drain старого snapshot'а.** Соединения на старой версии доживают на ней, затем
её можно освободить.

## Фичи диплома

**DPI (Deep Packet Inspection).** Разбор содержимого пакетов. У нас — задумка
zero-alloc разбора JSON (F3, future work).

**Zero-alloc DPI JSON.** Потоковый разбор JSON без аллокаций (нужен L7-этап).

**Sliding-window rate limit.** Ограничение по **скользящему** окну времени
(кольцевые бакеты), а не по фиксированному «стаканчику». Точнее и плавнее
фикс-окна. Наша первая фича ядра (F2).

**Token bucket.** «Ведро токенов»: пополняется с заданной скоростью, каждый
запрос берёт токен. Основа для плавного `throttle`.

**Throttle / deny.** Вердикты фильтра: `throttle` — притормозить, `deny` — резать
(с TTL/backoff).

**LRU-эвикция.** Вытеснение самых «давно не использованных» ключей, чтобы таблица
не росла бесконечно.

**EWMA.** Экспоненциально взвешенное среднее — сглаженная оценка «нормы», с
которой сравниваем текущую активность.

**/24-агрегация.** Группировка адресов по подсети (IPv4 /24), чтобы ловить атаку
с «роя» близких IP.

**eBPF / XDP.** Фильтрация в ядре Linux до user space (F4, future work).

## Расширяемость

**WASM (WebAssembly).** Платформо-независимый байт-код; компилируешь плагин из
любого языка (Rust, C#, TinyGo, …) и исполняешь в песочнице. **Киллер-фича**
WasmGate.

**Sandbox.** Изоляция плагина: ограничения памяти/времени, отсутствие прямого
доступа к сети/ФС.

**Host functions.** Функции, которые ядро даёт плагину (лог, метрики, доступ к
запросу).

**wazero.** Чистый Go-рантайм WebAssembly (без CGO). Планируется как хост
плагинов.

**ABI.** Контракт вызова между плагином и ядром (набор host functions и
структура данных).

**Control Plane (C#/.NET).** Отдельный сервис управления: версии конфига,
реестр плагинов, публикация, откат (F1).

**Data Plane (Go).** Ядро, которое реально проксирует трафик.
