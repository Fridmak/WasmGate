# Development

## Requirements

- Go 1.26+ (the module pins a 1.27 toolchain through `go.mod`).
- `make` is optional; every target is a single `go` command.
- .NET 10 SDK for the control plane; `clang` + `zlib` for its Native AOT publish.
- `protoc`, `protoc-gen-go`, `protoc-gen-go-grpc` only when the gRPC contract
  changes.

## Repository layout

```
cmd/wasmgate/          flags and process wiring
internal/config/       YAML schema, defaults, validation, reload
internal/proxy/        listeners, pools, relay, snapshot
internal/plugin/       WASM sandbox and ABI
internal/tlspeek/      ClientHello/SNI parser
internal/ratelimit/    sliding window and concurrency guard
internal/observe/      logs, metrics, admin endpoint
internal/controlplane/ control-plane client
plugins/examples/      Rust workspace with reference plugins
control-plane/         C# solution and xunit tests
configs/               example and showcase configuration
deployments/           systemd, Dockerfiles, compose, dev certificates
benchmarks/            raw benchmark output
docs/en, docs/ru       product documentation (both languages)
```

## Build and run

```bash
make build                 # bin/wasmgate
go build ./...             # compile everything
go run ./cmd/wasmgate -config configs/wasmgate.yaml -validate
go run ./cmd/wasmgate -config configs/wasmgate.yaml
```

## Tests

```bash
go test ./...              # unit + e2e over loopback
make race                  # go test -race ./...
go test ./internal/proxy   # one package
go test -run TestReload ./internal/proxy
```

Tests live next to their source (`X.go` → `X_test.go`): first the tests, then the
benchmarks for that file. End-to-end tests start a real server on loopback and,
when `nginx`/`haproxy` are installed, compare against them (otherwise they skip).

## Formatting and lint

```bash
gofmt -l .                 # must print nothing
go vet ./...
golangci-lint run          # v2.15.0, config in .golangci.yml
```

CI runs the same commands on Ubuntu and Windows plus a race-enabled test run on
Linux.

## Benchmarks

```bash
make bench
go test -run '^$' -bench BenchmarkThroughput -benchmem ./internal/proxy
benchstat old.txt new.txt
```

Methodology, interpretation and results are in [benchmarks](benchmarks.md); raw
output stays in `benchmarks/`.

## Profiling

Enable `admin_pprof: true` and keep the admin endpoint on loopback, then use
`go tool pprof http://127.0.0.1:9099/debug/pprof/profile` or `/heap`. CPU profiles
of the relay show `splice`/`copy` on the hot path; a mutex or semaphore there is a
bug, not a tuning opportunity.

## Control plane

```bash
cd control-plane
dotnet build WasmGate.Control.sln -c Release
dotnet test  WasmGate.Control.sln -c Release
dotnet format WasmGate.Control.sln --verify-no-changes
```

The API project targets Native AOT; a framework-dependent publish is enough for
local work:

```bash
dotnet publish src/WasmGate.Control.Api -c Release -p:PublishAot=false -o out
```

Native AOT needs a C toolchain (MSVC on Windows, `clang` + `zlib` on Linux).

The shared gRPC contract is `control-plane/src/WasmGate.Control.Api/Protos/agent_control.proto`.
After editing it:

```bash
make proto    # regenerate internal/controlplane/wasmgatepb
```

C# bindings are generated by the build; Go bindings are checked in.

## Documentation rule

Every tracked document exists in both languages: `README.md` / `README.ru.md`,
and `docs/en/...` / `docs/ru/...`. Change both in the same commit. Internal
material used for non-product work lives in the gitignored `thesis/` directory and
must never be linked from product docs or code.
