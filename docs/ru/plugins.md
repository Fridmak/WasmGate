# Плагины (ABI v4)

WasmGate исполняет L4- и L7-плагины через `wazero`. Все девять собранных
[примеров](../../plugins/examples/README.md) используют ABI v4. Загрузчик
отклоняет модули v3; старого рантайма и fallback нет. Экспорты, биты
возможностей и формат сообщений описаны в [контракте ABI v4](../en/plugin-abi-v4.md).

## Режимы инспекции

| `data_mode` | Что проверяется | Маршрутизация |
|---|---|---|
| Не задан | L4: `on_accept`, `on_close` или `on_close_ex` | Нет |
| `once` | Первое чтение клиента до подключения к бэкенду | Да |
| `headers` | Полные индексированные заголовки HTTP/1 до подключения к бэкенду | Да |
| `stream` | Блоки байтов в обоих направлениях | Нет |

- Без `body_policy` режим `headers` проверяет **только первый запрос**.
  Следующие запросы keep-alive проходят без инспекции. Поддерживаются
  HTTP/1.0 и HTTP/1.1 с CRLF. Размер заголовков ограничен `max_header_bytes`
  (по умолчанию 16 КиБ) и 512 полями; сбор ограничен `inspect_timeout`.
  Для `headers` требуется положительный `timeout`.
- `once` проверяет первое чтение, а не полное сообщение. `stream` видит
  границы чтений, а не запросов. Оба режима не меняют данные. При
  `idle_timeout: 0` режимы `once` и `headers` без body-политики могут
  вернуться к `splice(2)` на Linux.
- При терминации TLS плагин получает открытые данные. При passthrough он
  видит зашифрованный поток. `headers` несовместим с SNI-маршрутизацией без
  терминации TLS.

## Политика HTTP-тела

```yaml
plugin:
  path: "../plugins/examples/http_body_guard/http_body_guard.wasm"
  data_mode: headers
  timeout: 1s
  inspect_timeout: 3s
  body_policy: both          # request, response или both
  mutation_policy: replace  # по умолчанию none; replace требует CapMutation
```

**Любая `body_policy` ограничивает соединение одним HTTP/1-обменом.**
Прокси проверяет границы сообщений в обоих направлениях; настройка лишь
выбирает, какие данные получает плагин. При `response` и `both` он также
получает заголовки ответа. После первого финального ответа прокси закрывает
оба сокета, даже если бэкенд оставляет соединение открытым. Заголовки при
этом не переписываются.

- Запрос без `Content-Length` считается запросом без тела. Для ответа
  требуется один корректный `Content-Length`, кроме HEAD и статусов 204,
  205 и 304. Длина в ответе на HEAD или в 304 относится к представлению, не
  к телу. `max_body_bytes` (по умолчанию 1 МиБ) ограничивает заявленную длину
  в обоих направлениях и проверяется до чтения тела. `Transfer-Encoding`
  (включая chunked), тело до EOF, CONNECT, апгрейды, `Expect` и промежуточные
  ответы не поддерживаются.
- Заголовки ответа удерживаются до проверки. `inspect_timeout` отсчитывается
  от первого байта ответа; чтобы ограничить ожидание молчащего бэкенда,
  задайте `idle_timeout`. Чтение, захватившее данные за границей тела,
  отклоняется; следующий обмен не пересылается. Ошибка транспорта до конца
  тела закрывает соединение. Ранний финальный ответ может прервать загрузку.
- `mutation_policy: replace` разрешает замену проверяемого блока байт только
  на блок той же длины. Мутации заголовков запрещены. Ошибка политики
  закрывает соединение; уже отправленные байты при этом отозвать нельзя.
  Прокси не декодирует сжатие и не пересчитывает прикладные контрольные суммы.
- Состояние необязательно: если плагин объявил обе state-возможности,
  прокси хранит отдельное ограниченное состояние для каждого направления.
  Оно применяется после успешной проверки разрешающего результата.
  Глобальные переменные WASM не заменяют состояние соединения: инстансы
  переиспользуются.

## Песочница и миграция

У гостя нет WASI, доступа к сокетам, файлам, часам и генератору случайных чисел.
По умолчанию лимит памяти — 17 страниц (1,06 МиБ) на инстанс; дополнительная
страница нужна выровненным linker Rust-гостям. Движок ограничивает число
простаивающих инстансов, а `max_instances` (по умолчанию 64, жёсткий предел
1024) ограничивает число одновременных инстансов на listener; запросы сверх
лимита ждут слот или завершаются по дедлайну. `max_conns`, если задан,
ограничивает число активных соединений. Загрузка ограничена 5 с, у хука свой
`timeout` (по умолчанию 1 с). Ошибка или таймаут закрывает соединение и
уничтожает инстанс.

## Отличия от legacy-рантайма v3

ABI v4 — меньший fail-closed контракт, а не полная замена всех возможностей v3.
Следующие поведения v3 намеренно отсутствуют:

- мутация непрозрачных чанков `stream`; замены доступны только для событий
  тела при `body_policy` и `mutation_policy: replace`;
- постоянное состояние между произвольными чанками потока и состояние
  keep-alive между обменами; состояние существует только для фаз
  заголовков/тела, выбранных `body_policy`;
- fallback с `on_headers` на `on_data`; модуль обязан экспортировать v4-хуки
  `on_event` для объявленного плана.

Развёртыванию, которое зависит от этих возможностей, нужен редизайн гостя или
конфигурации, а не только пересборка.

При переходе с v3 пересоберите плагины: добавьте `wg_abi` и `wg_caps`, замените
L7-хуки на `on_event` и используйте OUT для состояния и замен. L4-плагин
объявляет `CapLifecycle`. Плагины ранней реализации v4, которые меняют тело,
теперь требуют `mutation_policy: replace` в конфигурации.

```bash
cd plugins/examples
cargo test --locked -p wg-common
cargo build --locked --workspace --release --target wasm32-unknown-unknown
```

Демо: [`configs/showcase.yaml`](../../configs/showcase.yaml). Проверка:
`wasmgate -config configs/showcase.yaml -validate`.
