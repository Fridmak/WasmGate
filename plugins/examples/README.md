# Примеры WASM-плагинов и ограничения песочницы (`internal/plugin`)

В `plugins/examples/ipguard/` лежит эталонный плагин фильтрации соединений
(**IP Guard**) в двух исходных вариантах — **Rust (`#![no_std]`)** и **TinyGo** —
а также готовый скомпилированный бинарник `ipguard.wasm` (63 байта), который
можно сразу подключить в конфиг без установки внешних компиляторов:

```yaml
listeners:
  - name: edge
    addr: "127.0.0.1:8080"
    upstream_pool: web
    plugin:
      path: "plugins/examples/ipguard/ipguard.wasm"
      max_memory_pages: 16   # 16 * 64 KiB = 1 MiB потолок памяти на инстанс
      timeout: 0s            # 0s = без таймера на вызов (0 allocs/op)
```

---

## 1. Контракт ABI (Go Host ↔ WASM Guest)

Ядро передаёт метаданные соединения **через стек регистров (`uint64`)** с помощью
`wazero` `CallWithStack`, без выделения строк и без копирования в линейную память
WASM. Это даёт **0 B/op и 0 allocs/op** (~91 нс в один поток, ~15 нс параллельно).

Модуль обязан экспортировать хотя бы одну из двух функций со следующей сигнатурой:

| Экспорт | Сигнатура WASM | Аргументы | Возврат |
|---------|----------------|-----------|---------|
| `on_accept` | `(i64, i64, i32) -> i32` | `ip_hi`, `ip_lo` (16-байтный канонический IP в big-endian; для IPv4 это `::ffff:a.b.c.d`, т.е. `ip_hi = 0`, `ip_lo = 0x0000ffff_AABBCCDD`), `port` (TCP-порт клиента) | `0` = `VerdictAllow` (пропустить), любое ненулевое (`1`) = `VerdictDeny` (сбросить до `dial`) |
| `on_close` | `(i64, i64, i64, i64) -> ()` | `ip_hi`, `ip_lo`, `rx_bytes` (байт от бэкенда клиенту), `tx_bytes` (байт от клиента бэкенду) | пусто |

Если сигнатура экспорта не совпадает или модуль не экспортирует ни `on_accept`,
ни `on_close`, загрузка конфигурации / `Reload` завершается ошибкой до смены
snapshot'а (fail-fast).

## 2. Жёсткие ограничения на плагины (чего плагин делать НЕ может)

Эти ограничения — осознанный компромисс ради безопасности и `0 allocs/op` на
горячем пути (важно явно проговаривать на защите ВКР):

1. **Полное отсутствие WASI и системных вызовов (Pure Sandbox).**
   Гостевому модулю **не** предоставляются файловая система, сетевые сокеты,
   переменные окружения, системные часы или генератор случайных чисел. Плагин —
   чистая детерминированная функция от переданных метаданных соединения.
   Попытка импортировать `wasi_snapshot_preview1` без зарегистрированных хост-функций
   приведёт к отказу компиляции модуля на этапе старта/reload.
2. **Жёсткий потолок линейной памяти (`max_memory_pages`).**
   По умолчанию каждый инстанс ограничен **16 страницами (16 × 64 KiB = 1 MiB)**.
   - Если `.wasm` модуль в секции `memory` запрашивает `min > max_memory_pages`,
     он отвергается при загрузке (`TestPluginMemoryLimitRejectsOversizedModule`).
   - Если плагин внутри вызывает `memory.grow` сверх лимита, инструкция возвращает `-1`
     (выделение памяти внутри гостя получает OOM, не затрагивая процесс Go).
3. **Пул переиспользуемых инстансов (Reactor-модель, а не Command-модель).**
   Инстансы хранятся в `sync.Pool` и вызываются многократно для разных соединений:
   - глобальные переменные внутри WASM **сохраняются** между вызовами одного
     инстанса, но **не синхронизированы** между разными инстансами в пуле;
   - плагин не должен полагаться на то, что его глобальная память сбрасывается
     на каждое соединение, и не должен хранить секреты одного соединения в
     глобальном буфере.
4. **Ограничение по времени исполнения (`timeout`) и выбраковка при сбое.**
   - При `timeout > 0` включается `WithCloseOnContextDone(true)`: если хук
     зависает в бесконечном цикле или падает в `unreachable` (panic/trap),
     вызов принудительно прерывается, соединение отклоняется (`VerdictDeny`),
     а испорченный инстанс **закрывается и уничтожается**, а не возвращается в пул.
   - При `timeout: 0s` (по умолчанию) таймер на каждый вызов не создаётся, что
     сохраняет **0 аллокаций на соединение** (прерывание привязано к контексту
     жизни самого соединения).
5. **Уровень L4 (только метаданные соединения, без `on_data` в fast path).**
   В текущем L4-ядре плагин вызывается на границах жизни соединения (`on_accept`,
   `on_close`). Потоковый перехват полезной нагрузки (`on_data`) намеренно не
   включён в базовый путь, так как любая инспекция байтов в user-space отключает
   ядерный zero-copy `splice(2)` на Linux (см. `docs/02-architecture-tech.md`, §3.1).

## 3. Как собрать свой плагин

### Вариант А — Rust (`#![no_std]`, рекомендуемый)
```bash
cd plugins/examples/ipguard
rustup target add wasm32-unknown-unknown
cargo build --release --target wasm32-unknown-unknown
cp target/wasm32-unknown-unknown/release/ipguard.wasm ./ipguard.wasm
```

### Вариант Б — TinyGo
```bash
cd plugins/examples/ipguard/tinygo
tinygo build -o ../ipguard.wasm -target=wasm-unknown -no-debug .
```
